# 「树洞来信」手机端网站 MVP 设计规格

日期：2026-07-16  
状态：用户已批准，已按第一轮规格审查修订
部署目标：Vercel 上的真实可访问手机端网站

## 1. 产品概述

「树洞来信」是一个面向中国大陆用户的手机端时光胶囊网站。用户把一段话写给未来的自己，选择一年后、五年后、十年后或自定义日期启封。信件封存后正文不可查看、不可修改；到期后系统通过邮件提醒，用户登录后才能启封阅读。

产品的核心体验不是普通备忘录，而是具有仪式感的“写信—封存—等待—启封”闭环。

第一阶段是零成本、小范围真实测试。它必须能够部署、登录、持久化数据并完成真实提醒演练，但不对一年、五年、十年的免费服务可用性作绝对承诺。用户增长后再升级数据库、备份和通知服务。

## 2. 目标与成功标准

### 2.1 产品目标

- 让用户在手机上快速写下一封给未来自己的信。
- 通过不可提前阅读的封存规则，建立时间胶囊的仪式感。
- 到期后可靠地解锁信件，并尽力向用户发送提醒。
- 业务模块保持通知渠道可扩展，但 MVP 不提前存储手机号或实现短信接口。
- 让第一次部署经验较少的项目所有者能够按照中文说明完成配置和上线。

### 2.2 MVP 成功标准

- Vercel 生产环境存在真实可访问链接。
- 站长本人能完整完成邮箱验证码登录、写信、封存、到期、提醒和启封。
- 未到期正文不能通过页面或普通 API 请求读取。
- 启封日期修改规则、删除规则和提醒幂等规则由服务端强制执行。
- 375px、390px 和 430px 宽度的主流手机视口可正常使用。
- 项目包含可重复执行的自动测试与中文部署文档。

## 3. 用户范围与产品边界

### 3.1 目标用户

- 第一阶段主要面向中国大陆用户。
- MVP 使用邮箱验证码登录；获得国内短信签名资质后再增加手机号登录和短信提醒。
- 产品界面为中文，时间按中国标准时间展示。

### 3.2 MVP 范围

- 邮箱六位验证码登录，无密码。
- 创建纯文字信件。
- 一年后、五年后、十年后、自定义日期四种启封时间选择。
- 封存前二次确认。
- 未启封信件列表、倒计时和状态展示。
- 未启封信件删除。
- 启封日期仅可修改一次。
- 到期邮件提醒、失败记录与重试。
- 到期后本人启封阅读。
- 删除账号及其信件数据。
- 面向站长的最小日志排查能力。

### 3.3 明确不做

- 匿名广场、公开信件、点赞、评论和内容审核。
- 图片、音频、视频或附件。
- 手机号验证码和短信提醒。
- 微信登录、密码登录和多因素认证。
- 支付、订阅或会员体系。
- 原生 App、小程序或桌面客户端。
- 复杂管理后台。
- 严格端到端加密。
- 个人数据导出；避免未到期正文导出语义扩大首版范围，后续单独设计。

社区功能作为第二阶段独立设计，不在 MVP 页面中展示“即将上线”占位入口。

## 4. 核心业务规则

### 4.1 写信与封存

- 信件必须包含标题、正文和启封日期。
- 标题为 1 至 50 个 Unicode 字符，正文为 1 至 10,000 个 Unicode 字符；前端用于即时反馈，服务端为最终校验方。
- 快捷日期按当前中国标准日期计算一年、五年或十年后；遇到闰日等无对应日期时采用目标月份的最后一个有效日期。
- 自定义日期最早为中国标准时间的次日，最晚为当前日期十年后。MVP 按“日期”而非任意时分选择。
- 所选日期统一映射为该日 `Asia/Shanghai` 00:00:00，对应的 UTC 瞬间写入 `unlock_at`；当数据库时间 `now() >= unlock_at` 时即可启封。
- 用户提交前必须看到不可修改正文、可删除和时间仅能修改一次的说明。
- 免费体验版还必须单独确认：“当前为测试服务，不保证信件可持续保存一年、五年或十年；正式长期保障将在备份和付费基础设施上线后提供。”该确认版本随信件记录，避免长期选项被误解为无条件承诺。
- 封存请求成功后才播放完成态动画；数据库写入失败时不得展示虚假的成功状态。

### 4.2 封存后的访问

- 到期前只返回标题、写信日期、启封日期、倒计时所需时间和是否修改过日期。
- 到期前服务端不得把正文放入页面 HTML、React Server Component 载荷或 API 响应。
- 到期前允许返回的字段采用显式白名单；不得返回密文、IV、认证标签、密钥 ID或任何正文派生长度。
- 修改手机时间不能提前启封；所有状态判断以数据库或服务端时间为准。
- 到期后用户仍须通过自己的登录会话读取正文。

### 4.3 修改启封日期

- 只有未到期、未删除的信件可以修改启封日期。
- 每封信最多成功修改一次。
- 新日期必须晚于修改请求发生时。
- 数据库保存原日期、新日期、修改时间和递增的启封版本号。
- 修改必须通过单个受控数据库函数或等价的单条条件更新完成，其条件至少包含 `user_id = 当前会话用户`、`unlock_at > transaction_timestamp()`、`unlock_changed_at IS NULL` 和“新日期晚于数据库当前时间”。更新启封时间、修改时间和版本号必须在同一原子操作完成，且只有影响一行才算成功。
- 浏览器角色不能直接更新这些列。并发、重放、过期瞬间提交或跨用户请求中只能有一个合法请求成功。

### 4.4 删除

- 用户可以删除自己的未启封或已启封信件。
- 删除前必须二次确认，并明确不可恢复。
- MVP 使用受控服务端事务执行永久删除：先锁定本人信件，再级联删除提醒记录与信件密文。成功响应后不可恢复。
- 用户不能访问或删除其他用户的信件。

### 4.5 到期与提醒

- 信件是否可启封只取决于启封时间，不取决于提醒是否成功。
- 到期邮件的主题和正文均使用通用文案，只说明有信件可启封并附网站链接，不包含标题或正文，避免锁屏预览泄露隐私。
- `event_key` 由 `letter_id + unlock_version + unlock_at` 确定；修改启封日期会产生新版本，旧版本的未发送记录作废，删除信件会级联删除全部提醒记录。
- 发送保证定义为“至少一次、尽力避免重复”，不承诺跨外部邮件服务的数学意义恰好一次。系统向支持幂等的服务商发送稳定幂等键，并对不确定结果进行状态查询或人工核对。
- 发送记录具有租约字段；任务崩溃后，超过 15 分钟的 `sending` 记录可被下一次任务安全接管。
- 失败提醒记录错误类型和尝试次数。可重试错误最多尝试 5 次，退避为 1 天、1 天、2 天、3 天；无效收件地址等终止错误不自动重试。MVP 仅允许站长从日志和受保护工具触发额外重试，不提供用户重试接口。

### 4.6 信件状态转换

| 当前状态 | 条件或操作 | 下一状态 | 正文可返回 | 允许的主要操作 |
|---|---|---|---|---|
| `sealed` | 数据库时间尚未到 `unlock_at` | `sealed` | 否 | 查看元数据、修改一次日期、永久删除 |
| `sealed` | `now() >= unlock_at` | `due_unopened` | 仅在详情启封请求中 | 启封、永久删除 |
| `due_unopened` | 本人首次成功读取正文 | `opened`，原子写入 `opened_at` | 是 | 阅读、永久删除 |
| `opened` | 再次访问 | `opened` | 是 | 阅读、永久删除 |
| 任意存在状态 | 本人确认永久删除 | 资源不存在 | 否 | 无 |

`due_unopened` 是由服务器时间推导的状态，不依赖 Cron 或邮件是否执行。首次启封写入必须幂等，重复请求只能得到同一正文和同一 `opened_at`。

## 5. 信息架构与页面

### 5.1 首页

- 品牌名称、核心文案和一封拟物旧信作为视觉焦点。
- 主操作：“写给未来”。
- 已登录用户可进入“我的树洞”；未登录用户进入登录流程。
- 不展示社区入口。

### 5.2 登录页

- 输入邮箱并请求六位验证码。
- 验证码有效期 10 分钟且只能使用一次；同一邮箱和 IP 60 秒内不得重发，每小时最多请求 5 次，同一验证码最多验证 5 次。
- 请求验证码始终返回相同的中性提示，避免泄露邮箱是否已注册；达到风控阈值时启用 CAPTCHA。
- 明确提示邮件可能延迟以及垃圾邮件箱检查方式。
- 登录成功后只允许返回站内相对路径，拒绝外部 URL，防止开放重定向。
- 会话过期时，写操作必须失败并要求重新登录；重新登录后返回原站内页面，但不自动重放写操作。

### 5.3 写信页

- 标题输入、正文书写区、快捷日期和自定义日期。
- 支持浏览器会话内本地草稿，网络错误或意外刷新后可恢复。
- 本地草稿只用于封存前恢复；封存成功后立即清除。
- 提交后进入封存确认层，长按封蜡按钮约一秒完成确认。

### 5.4 我的树洞

- 默认按启封时间排序，明确区分 `sealed`（未到期）、`due_unopened`（已到期未读）和 `opened`（已读）三种可见状态；已删除信件不出现在列表。
- `sealed` 卡片展示封闭信封、标题、写信日期、启封日期和倒计时。
- `due_unopened` 卡片展示可拆封信封与“现在启封”。
- `opened` 卡片展示展开信纸状态。
- 空状态引导用户写第一封信。
- 列表需要定义加载、网络失败和重试状态。

### 5.5 信件详情

- 未到期时只显示信封外部信息、修改一次日期和删除操作。
- 日期已修改后，修改入口永久禁用并解释原因。
- 到期后首次成功读取时原子地写入 `opened_at`，播放可跳过的拆信动画，再展示正文；刷新后不强制重播动画，但用户可主动再次观看。
- 长正文保持舒适行高、段落和滚动体验。
- 邮件深链接在会话失效时先进入登录，成功后安全返回该信件；不存在、已删除和无权限统一使用不泄露资源存在性的错误页。

### 5.6 设置页

- 显示当前邮箱和邮件提醒说明；MVP 的到期邮件是产品核心流程，不提供关闭开关。
- 退出登录。
- 删除账号：再次输入邮箱验证码确认，立即阻止新会话，并在受控服务端流程中永久删除提醒记录、信件、资料和 Supabase Auth 身份。
- 不为手机号绑定预留空字段或不可用入口；未来通过数据库迁移添加。

## 6. 视觉与交互设计

### 6.1 视觉方向

采用拟物化复古书信风，而非现代扁平风。

- 背景：深色旧木桌、低对比木纹和克制暗角。
- 主体：旧牛皮纸、泛黄信纸、轻微纸张纤维、折痕和边缘磨损。
- 主色：灰褐、旧牛皮纸、泛黄米色、烟灰棕、旧墨黑和褪色咖色。
- 点缀：少量褪色邮戳红或封蜡红。
- 光线：模拟深夜台灯下的局部暖光。
- 气质：复古、沉静、怀旧、克制、温柔且略带忧郁。

纹理需要精致且低对比，不得影响可读性或显得脏乱廉价。

### 6.2 字体

- 标题、日期、按钮和短标签使用自然优雅的手写体或字帖感字体。
- 正文使用具有书信感且屏幕可读性好的宋体或楷体回退栈。
- 手写字体不得用于长正文。
- 中文正文移动端字号不低于 16px，默认行高约 1.8，用户缩放后不得截断。

### 6.3 动效

- 首页信封可有轻微光影呼吸效果。
- 封存可采用长按封蜡、盖章和信封合拢动效，但长按不是唯一完成方式；键盘、辅助技术和运动控制用户可通过普通“确认封存”按钮完成相同操作。
- 启封采用约 1 至 1.5 秒的拆信与展开动效。
- 动效必须可跳过，并尊重 `prefers-reduced-motion`。
- 数据请求失败时不能用成功动画掩盖失败。

### 6.4 移动端与可访问性

- 优先适配 375px 至 430px 宽度。
- 触控区域不小于 44px。
- 键盘弹出时，正文输入和主要操作仍可见或可滚动到达。
- 以 WCAG 2.2 AA 为目标：普通文字对比度至少 4.5:1，大字和 UI 图形至少 3:1，焦点指示清晰且不被遮挡。
- 表单具有语义标签和错误关联；异步保存、封存成功或失败使用 live region 通知屏幕阅读器；任何状态不得仅靠颜色表达。
- 支持 200% 文本缩放和 400% 页面缩放下的单列重排，并适配手机安全区域。
- 纸张纹理不能替代结构信息或降低对比度。
- 桌面端使用居中的手机阅读宽度，不把信纸无意义拉宽。

## 7. 技术架构

### 7.1 技术栈

- 前端与全栈框架：React、Next.js App Router、TypeScript。
- 样式：Tailwind CSS、CSS 变量和少量专用 CSS 动画。
- 后端：Next.js Route Handlers，部署为 Vercel Functions。
- 数据库：Supabase PostgreSQL。
- 身份认证：Supabase Auth 邮箱 OTP。
- 数据访问：服务端 Supabase SDK 与数据库 Row Level Security；浏览器不直接访问业务表。
- 邮件：Resend，作为 Supabase Auth 自定义 SMTP 和业务提醒发送服务。
- 定时任务：Vercel Cron。
- 输入校验：Zod。
- 单元与集成测试：Vitest。
- 端到端测试：Playwright。

### 7.2 代码边界

采用单仓库模块化单体结构：

- `app/`：路由、页面、布局和 Route Handlers。
- `features/auth/`：登录表单、会话与授权逻辑。
- `features/letters/`：写信、封存、列表、启封、修改与删除。
- `features/reminders/`：到期查询、发送状态、租约恢复、站长重试和邮件模板。
- `components/`：可复用的信纸、信封、按钮、表单和反馈组件。
- `lib/db/`：数据库客户端、查询和生成类型。
- `lib/security/`：加解密、授权断言、速率限制、幂等与安全重定向工具。
- `lib/time/`：UTC、中国标准时间、快捷日期和倒计时计算。

业务规则放在可独立测试的服务函数中，不散落在页面组件内。API 层负责验证、授权和映射 HTTP 响应，不直接承载全部业务细节。

### 7.3 浏览器与数据库权限矩阵

- `anon` 与 `authenticated` 数据库角色不拥有 `letters`、`reminder_deliveries` 基础表的直接 `SELECT`、`INSERT`、`UPDATE` 或 `DELETE` 权限。
- 浏览器只调用 Supabase Auth 官方端点和本站 Next.js API，不直接查询业务表。
- 所有信件读写都经过 Next.js 服务端；返回值使用字段白名单，密文相关列永不序列化给浏览器。
- Service Role 密钥只存在于 Vercel 服务端，绝不使用 `NEXT_PUBLIC_` 前缀，也不进入日志、客户端包或仓库。
- 每次使用 Service Role 前，路由必须先从用户会话取得用户 ID，再在查询条件中显式约束所有权和业务状态。Service Role 不能被视为可以跳过应用层授权的理由。
- RLS 保持默认拒绝，作为服务端错误配置时的纵深防御；必要的数据库函数使用固定 `search_path`、最小权限和显式所有权检查。

## 8. 数据模型

### 8.1 profiles

- `id`：与 Supabase Auth 用户 ID 对应。
- `email`：由 Supabase Auth 身份中的规范化邮箱同步，Auth 为权威来源；资料创建使用幂等数据库触发器或事务，避免首次登录竞态。
- `timezone`：MVP 默认 `Asia/Shanghai`。
- `created_at`、`updated_at`。

### 8.2 letters

- `id`。
- `user_id`。
- `title`：封存前后均需在列表展示，因此不作为正文密文的一部分，但仍受 RLS 保护。
- `body_ciphertext`、`body_nonce`、`encryption_version`、`key_id`。
- `created_at`。
- `unlock_at`：UTC 时间。
- `original_unlock_at`：首次设置值。
- `unlock_changed_at`：为空表示尚未修改。
- `unlock_version`：初始为 1，日期成功修改后原子递增。
- `opened_at`：用户首次成功阅读时间。
- `created_idempotency_key`：防止重复封存。
- `terms_version`：记录封存时确认的体验版长期保存声明版本。

### 8.3 reminder_deliveries

- `id`。
- `letter_id`。
- `user_id`。
- `channel`：MVP 为 `email`，未来可为 `sms`。
- `event_key`：由信件 ID、启封版本和启封时间确定，唯一标识本次到期事件。
- `status`：`pending`、`sending`、`sent`、`failed`。
- `attempt_count`。
- `provider_message_id`。
- `last_error_code`、`last_error_message`。
- `locked_at`、`lease_expires_at`、`next_attempt_at`、`sent_at`、`created_at`、`updated_at`。

数据库为 `(letter_id, channel, event_key)` 设置唯一约束。信件永久删除时提醒记录通过外键级联删除。业务表不向浏览器角色开放直接权限，RLS 保持默认拒绝；使用服务端高权限密钥的定时任务只能运行在受保护的服务端环境。

## 9. 加密与隐私边界

- 信件正文在 Next.js 服务端使用 AES-256-GCM 加密后写入数据库。
- 每封信使用密码学安全随机数生成器产生独立 96 位 nonce；认证标签由标准 AES-GCM 输出携带，不自行拼装非标准格式。
- 认证附加数据至少绑定 `letter_id`、`user_id`、`encryption_version`，防止密文被换绑到另一封信或用户。
- 加密密钥只保存在 Vercel 的 Production 加密环境变量和受控离线备份中，不进入 Preview、客户端包、日志或 Git。开发和测试使用独立密钥。
- 数据库存储非秘密的 `key_id` 和 `encryption_version`。服务端使用版本化 keyring：新信使用当前密钥，旧密钥在完成重加密和校验前保留只读解密能力。
- 解密函数必须先完成会话、所有权和到期时间检查；已永久删除的资源统一按不存在处理。
- 日志不得记录验证码、会话令牌、正文、密钥或完整邮件内容。
- 标题为满足到期前列表展示而不加密，但仍是私密数据，只允许所有者读取。
- API 不返回密文或正文派生长度；本规格不承诺通过密文填充隐藏数据库管理员可见的近似正文长度。

这不是严格端到端加密。服务端在满足启封条件后有能力解密正文。MVP 选择这一边界，是为了兼顾账号恢复、服务端到期校验和未来通知扩展。

密钥丢失将导致正文不可恢复。邀请外部测试用户前必须建立双人可审计的离线备份保管说明、恢复演练记录和密钥轮换步骤；轮换测试需要证明新旧信件均可解密、错误密钥必然失败，且旧密钥只有在全部记录重加密并抽样校验后才可退役。

## 10. API 与授权

建议接口职责如下，最终路径可在实施计划中细化：

- `POST /api/letters`：创建并封存信件。
- `GET /api/letters`：返回本人信件元数据列表。
- `GET /api/letters/:id`：到期前仅返回元数据，到期后返回解密正文。
- `PATCH /api/letters/:id/unlock-date`：原子地修改一次启封日期。
- `DELETE /api/letters/:id`：永久删除本人信件及提醒记录。
- `DELETE /api/account`：二次 OTP 验证后删除本人业务数据和 Auth 身份。
- `GET /api/cron/reminders`：受 `CRON_SECRET` 保护的提醒任务。
- 站长额外重试不开放公网用户接口；通过受保护的运维脚本或仅服务端管理动作执行。

所有写操作执行以下共通步骤：

1. 验证登录会话。
2. 解析并校验请求体。
3. 重新查询资源所有权和当前状态。
4. 在服务端执行业务规则。
5. 使用事务、唯一约束或条件更新保证并发安全。
6. 返回稳定错误码和适合用户阅读的中文提示。

核心错误码至少包含：`AUTH_REQUIRED`、`SESSION_EXPIRED`、`VALIDATION_ERROR`、`LETTER_NOT_FOUND`、`LETTER_LOCKED`、`LETTER_ALREADY_OPEN`、`UNLOCK_DATE_CHANGE_USED`、`UNLOCK_DATE_INVALID`、`RATE_LIMITED`、`REMINDER_TERMINAL_FAILURE` 和 `INTERNAL_ERROR`。不存在、无权限和已删除的信件统一返回 `LETTER_NOT_FOUND`，避免资源枚举。

### 10.1 认证与账号状态

- Supabase Auth 是邮箱和身份 ID 的权威来源，`profiles` 只保存同步副本。
- OTP 状态为“已请求—已验证或已过期/已用尽”，过期、重复使用和超过尝试次数均拒绝。
- 会话失效、账号禁用或删除后，任何业务读取和写入均拒绝。
- 账号删除先标记 Auth 用户不可继续建立会话，再在服务端事务中删除提醒、信件和资料，最后删除 Auth 身份；任一步失败都记录站长告警并保持账号不可登录，直到补偿流程完成。
- “退出登录”结束当前设备会话；“删除账号”结束全部会话并永久删除数据。外部测试前需在界面说明平台和邮件服务日志可能按各服务商政策保留有限时间。

## 11. 提醒与时间处理

- 数据库统一保存 UTC 时间，界面使用 `Asia/Shanghai` 展示。
- 信件在所选日期的中国标准时间 00:00 起可启封。Vercel Cron 配置为每天 `02:00 UTC` 运行一次，Hobby 套餐可能在该小时内任意时间调用，因此预期提醒窗口为中国标准时间 10:00 至 10:59，产品只承诺“到期日上午尽力提醒”。
- Cron 查询已到期、信件仍存在且当前 `event_key` 没有成功或终止提醒的记录。日期修改在数据库时间到期前才允许，因此不会与合法的已到期发送并存；版本号仍用于拒绝陈旧任务。
- Cron 接口使用 `CRON_SECRET` 验证来源，不能匿名公开执行。
- 任务以 15 分钟租约和条件更新领取发送记录，防止并发任务同时发送；过期租约可恢复。
- 向邮件服务发送稳定幂等键。若服务商已接收但本地写入前崩溃，下一次任务先按服务商消息 ID或幂等键核对；无法判定时允许重复提醒，并在文档中维持“至少一次”语义。
- 发送成功后保存服务商消息 ID；失败遵循第 4.5 节的错误分类、上限和退避计划，额外人工重试仅限站长。
- 即使提醒完全失败，用户访问网站时也能按服务端时间正常启封。

快捷日期与倒计时应由共享的时间模块计算，并对跨年、闰年、月底、时区边界，以及启封瞬间前、正好相等和之后编写测试。

## 12. 错误处理与恢复

- 网络错误：保留封存前本地草稿，提供重试，不自动创建重复信件。
- 登录邮件延迟：显示 60 秒重发倒计时和排查提示；服务端执行第 5.2 节的邮箱/IP 限流与验证码尝试上限。
- 数据库写入失败：明确告知未封存成功。
- 重复提交：客户端禁用按钮，服务端使用幂等键和唯一约束兜底。
- 未到期访问：返回稳定的禁止状态，不泄露密文或正文长度等不必要信息。
- 第二次修改日期：返回业务冲突错误，页面同步显示已用完机会。
- 邮件失败：按最多 5 次和明确退避计划重试，不影响启封；终止错误进入站长日志。
- 免费配额或服务暂停：站长日志必须能识别，不建设独立状态页，也不把故障显示为正常等待。
- 账号删除失败：立即阻止账号继续登录，记录补偿任务，由站长完成剩余数据清理并通知用户结果。

## 13. 测试与验收

### 13.1 单元测试

- 一年、五年、十年和自定义日期计算。
- 闰日、月底、UTC 与中国标准时间转换。
- 标题和正文长度校验。
- AES-GCM 加密后密文不等于明文，正确 keyring 可解密，错误 AAD、错误 key ID、错误密钥或篡改密文会失败。
- 到期判断及启封边界前、正好相等、之后三种情况。
- 日期仅可修改一次。
- 提醒租约、重试、终止错误和至少一次状态机。

### 13.2 数据库与集成测试

- 浏览器数据库角色不能直接读取或修改业务表；服务端只能返回字段白名单。
- 未到期详情不返回正文、密文、nonce、key ID 或正文派生长度。
- 并发、重放、跨用户、陈旧会话和到期瞬间的日期修改只有合法的第一个请求成功。
- 重复幂等键只创建一封信。
- 重复 Cron 调用不创建重复事件记录；模拟“服务商接受后本地崩溃”，验证核对流程或记录可接受的至少一次重复。
- 永久删除后列表、详情、启封和提醒均不可访问，关联提醒记录不存在。
- OTP 过期、重复使用、暴力尝试、邮箱/IP 限流、开放重定向、会话在写操作中失效和首次 profile 创建竞态均被正确处理。
- 账号删除结束全部会话并清除 Auth 身份、资料、信件和提醒记录。

### 13.3 端到端测试

- 邮箱登录、写信、封存、列表和退出。
- 通过测试时钟或测试数据完成到期与启封流程。
- 本地草稿恢复。
- 删除和二次确认。
- 日期修改一次后禁用。
- 375px、390px、430px 视口及手机软键盘场景。
- 长按之外可用普通按钮和键盘完成封存；屏幕阅读器能收到状态与错误通知。
- 减少动态效果设置下无强制拆信动画；完成 200% 文本缩放、400% 页面缩放和安全区域检查。
- 弱网、刷新和重复点击不生成重复数据。
- 支持矩阵至少包含 iOS Safari 16 及以上、Android Chrome 当前与前一个主要版本，以及主流微信内置浏览器的核心写信与启封路径。

### 13.4 生产演练

- Vercel 生产链接可访问。
- Supabase 生产 RLS 已启用。
- 环境变量未暴露到客户端或仓库。
- 使用站长本人邮箱完成一次真实 OTP 邮件和一次到期提醒。
- 验证提醒失败日志、租约恢复和站长重试路径。
- 按部署文档从空环境复现关键配置。
- 外部测试前，分别通过中国移动、联通、电信网络抽样检查站点可达性，并向 QQ 邮箱、163 邮箱及至少一种国际邮箱抽样检查验证码和提醒投递；结果写入发布检查记录，失败时不得宣称普遍可用。
- 使用自动化无障碍扫描加人工键盘和屏幕阅读器抽查，验证 WCAG 2.2 AA 的本规格要求。

## 14. 部署、成本与阶段策略

### 14.1 零成本自测

- Vercel Hobby 部署到 `*.vercel.app`。
- Supabase Free 保存数据和处理认证。
- Resend 测试域名只向 Resend 账号本人邮箱发送。
- 该阶段用于站长端到端测试，不对外承诺长期保存。

### 14.2 小范围外部测试

- 购买自有域名并绑定 Vercel。
- 在 Resend 验证域名，配置 SPF、DKIM，并作为 Supabase 自定义 SMTP。
- 继续使用 Resend、Vercel 和 Supabase 免费额度，直到达到容量或可靠性门槛。
- 发布最小隐私说明、测试版服务声明、数据保留与删除说明、联系邮箱和账号删除流程；用户首次封存前必须确认对应版本。
- 完成生产密钥离线备份、恢复演练、账号所有权记录，以及中国大陆移动网络和代表性邮箱的抽样测试。
- 一年、五年、十年选项可以用于验证产品意图，但封存前必须显著确认免费测试版不提供长期可用性保证。若要对外作出长期保存承诺，必须先完成第 14.3 节。

### 14.3 正式运营前必须补齐

- 升级不会因低活跃暂停且提供备份能力的数据库方案。
- 自动备份、恢复演练和密钥离线备份。
- 监控、错误告警、邮件退信和投递状态处理。
- 完整隐私政策、用户协议和可量化的服务期限承诺。
- 域名续费、账号所有权和服务交接流程。
- 获得合适资质后接入国内短信签名、模板和手机号验证。
- 明确平台日志、邮件投递日志与备份的保留期，并向用户披露账号删除后的清理边界。

不能以免费套餐为基础向用户作出“十年后必然可用”的无条件承诺。产品文案必须区分当前体验版与未来正式服务保障。

## 15. 后续扩展

按优先级考虑：

1. 自有域名和外部测试用户。
2. 数据备份、监控和付费稳定性升级。
3. 通过数据库迁移新增手机号绑定、短信验证码和短信到期提醒。
4. 图片或语音信件。
5. 匿名社区；需要重新设计公开授权、举报、审核、评论治理和管理员能力。

第二阶段功能不得提前污染 MVP 导航、数据权限或交互闭环。
