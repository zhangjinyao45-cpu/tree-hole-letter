# 「树洞来信」手机端网站 MVP 设计规格

日期：2026-07-16  
状态：用户已批准，待规格审查  
部署目标：Vercel 上的真实可访问手机端网站

## 1. 产品概述

「树洞来信」是一个面向中国大陆用户的手机端时光胶囊网站。用户把一段话写给未来的自己，选择一年后、五年后、十年后或自定义日期启封。信件封存后正文不可查看、不可修改；到期后系统通过邮件提醒，用户登录后才能启封阅读。

产品的核心体验不是普通备忘录，而是具有仪式感的“写信—封存—等待—启封”闭环。

第一阶段是零成本、小范围真实测试。它必须能够部署、登录、持久化数据并完成真实提醒演练，但不对一年、五年、十年的免费服务可用性作绝对承诺。用户增长后再升级数据库、备份和通知服务。

## 2. 目标与成功标准

### 2.1 产品目标

- 让用户在手机上快速写下一封给未来自己的信。
- 通过不可提前阅读的封存规则，建立时间胶囊的仪式感。
- 到期后可靠地解锁信件，并尽力向用户发送提醒。
- 为未来接入手机号验证和中国大陆短信服务保留清晰接口。
- 让第一次部署经验较少的项目所有者能够按照中文说明完成配置和上线。

### 2.2 MVP 成功标准

- Vercel 生产环境存在真实可访问链接。
- 站长本人能完整完成邮箱验证码登录、写信、封存、到期、提醒和启封。
- 未到期正文不能通过页面或普通 API 请求读取。
- 启封日期修改规则、删除规则和提醒幂等规则由服务端强制执行。
- 375px、390px 和 430px 宽度的主流手机视口可正常使用。
- 项目包含可重复执行的自动测试与中文部署文档。

## 3. 用户范围与产品边界

### 3.1 目标用户

- 第一阶段主要面向中国大陆用户。
- MVP 使用邮箱验证码登录；获得国内短信签名资质后再增加手机号登录和短信提醒。
- 产品界面为中文，时间按中国标准时间展示。

### 3.2 MVP 范围

- 邮箱六位验证码登录，无密码。
- 创建纯文字信件。
- 一年后、五年后、十年后、自定义日期四种启封时间选择。
- 封存前二次确认。
- 未启封信件列表、倒计时和状态展示。
- 未启封信件删除。
- 启封日期仅可修改一次。
- 到期邮件提醒、失败记录与重试。
- 到期后本人启封阅读。
- 导出个人数据。
- 面向站长的最小运行状态与日志排查能力。

### 3.3 明确不做

- 匿名广场、公开信件、点赞、评论和内容审核。
- 图片、音频、视频或附件。
- 手机号验证码和短信提醒。
- 微信登录、密码登录和多因素认证。
- 支付、订阅或会员体系。
- 原生 App、小程序或桌面客户端。
- 复杂管理后台。
- 严格端到端加密。

社区功能作为第二阶段独立设计，不在 MVP 页面中展示“即将上线”占位入口。

## 4. 核心业务规则

### 4.1 写信与封存

- 信件必须包含标题、正文和启封日期。
- 标题与正文需设置合理长度上限，并在前端和服务端同时校验。
- 快捷日期按当前中国标准日期计算一年、五年或十年后；遇到闰日等无对应日期时采用目标月份的最后一个有效日期。
- 自定义日期必须晚于当前日期。MVP 按“日期”而非任意时分选择，产品统一按该日期的提醒窗口处理。
- 用户提交前必须看到不可修改正文、可删除和时间仅能修改一次的说明。
- 封存请求成功后才播放完成态动画；数据库写入失败时不得展示虚假的成功状态。

### 4.2 封存后的访问

- 到期前只返回标题、写信日期、启封日期、倒计时所需时间和是否修改过日期。
- 到期前服务端不得把正文放入页面 HTML、React Server Component 载荷或 API 响应。
- 修改手机时间不能提前启封；所有状态判断以数据库或服务端时间为准。
- 到期后用户仍须通过自己的登录会话读取正文。

### 4.3 修改启封日期

- 只有未到期、未删除的信件可以修改启封日期。
- 每封信最多成功修改一次。
- 新日期必须晚于修改请求发生时。
- 数据库保存原日期、新日期和修改时间。
- 并发或重复请求中只能有一个成功；限制必须由数据库事务或原子条件更新保证。

### 4.4 删除

- 用户可以删除自己的未启封或已启封信件。
- 删除前必须二次确认，并明确不可恢复。
- MVP 采用软删除加后台清理策略：普通查询立即不可见，随后由受控清理任务永久删除密文和关联提醒记录。
- 用户不能访问或删除其他用户的信件。

### 4.5 到期与提醒

- 信件是否可启封只取决于启封时间，不取决于提醒是否成功。
- 到期邮件只说明有信件可启封并附网站链接，不包含标题之外的敏感内容，更不包含正文。
- 同一封信、同一通知渠道和同一到期事件最多存在一条成功提醒记录。
- 失败提醒记录错误类型和尝试次数，并在后续任务中重试。

## 5. 信息架构与页面

### 5.1 首页

- 品牌名称、核心文案和一封拟物旧信作为视觉焦点。
- 主操作：“写给未来”。
- 已登录用户可进入“我的树洞”；未登录用户进入登录流程。
- 不展示社区入口。

### 5.2 登录页

- 输入邮箱并请求六位验证码。
- 验证码重发需要倒计时和频率限制。
- 明确提示验证码有效期、邮件可能延迟以及垃圾邮件箱检查方式。
- 登录成功后返回用户原本想访问的页面。

### 5.3 写信页

- 标题输入、正文书写区、快捷日期和自定义日期。
- 支持浏览器会话内本地草稿，网络错误或意外刷新后可恢复。
- 本地草稿只用于封存前恢复；封存成功后立即清除。
- 提交后进入封存确认层，长按封蜡按钮约一秒完成确认。

### 5.4 我的树洞

- 默认按启封时间排序，可区分未启封与已启封。
- 未启封卡片展示封闭信封、标题、写信日期、启封日期和倒计时。
- 已启封卡片展示展开信纸状态。
- 空状态引导用户写第一封信。

### 5.5 信件详情

- 未到期时只显示信封外部信息、修改一次日期和删除操作。
- 日期已修改后，修改入口永久禁用并解释原因。
- 到期后播放可跳过的拆信动画，再展示正文。
- 长正文保持舒适行高、段落和滚动体验。

### 5.6 设置页

- 显示当前邮箱和提醒渠道状态。
- 导出个人数据。
- 退出登录。
- 为后续手机号绑定保留数据接口，但 MVP 不展示不可用入口。

## 6. 视觉与交互设计

### 6.1 视觉方向

采用拟物化复古书信风，而非现代扁平风。

- 背景：深色旧木桌、低对比木纹和克制暗角。
- 主体：旧牛皮纸、泛黄信纸、轻微纸张纤维、折痕和边缘磨损。
- 主色：灰褐、旧牛皮纸、泛黄米色、烟灰棕、旧墨黑和褪色咖色。
- 点缀：少量褪色邮戳红或封蜡红。
- 光线：模拟深夜台灯下的局部暖光。
- 气质：复古、沉静、怀旧、克制、温柔且略带忧郁。

纹理需要精致且低对比，不得影响可读性或显得脏乱廉价。

### 6.2 字体

- 标题、日期、按钮和短标签使用自然优雅的手写体或字帖感字体。
- 正文使用具有书信感且屏幕可读性好的宋体或楷体回退栈。
- 手写字体不得用于长正文。
- 中文正文移动端字号不低于 16px。

### 6.3 动效

- 首页信封可有轻微光影呼吸效果。
- 封存采用长按封蜡、盖章和信封合拢动效。
- 启封采用约 1 至 1.5 秒的拆信与展开动效。
- 动效必须可跳过，并尊重 `prefers-reduced-motion`。
- 数据请求失败时不能用成功动画掩盖失败。

### 6.4 移动端与可访问性

- 优先适配 375px 至 430px 宽度。
- 触控区域不小于 44px。
- 键盘弹出时，正文输入和主要操作仍可见或可滚动到达。
- 保持清晰的焦点状态、表单标签和错误提示。
- 纸张颜色与文字颜色需要达到可读对比度；纹理不能替代结构信息。
- 桌面端使用居中的手机阅读宽度，不把信纸无意义拉宽。

## 7. 技术架构

### 7.1 技术栈

- 前端与全栈框架：React、Next.js App Router、TypeScript。
- 样式：Tailwind CSS、CSS 变量和少量专用 CSS 动画。
- 后端：Next.js Route Handlers，部署为 Vercel Functions。
- 数据库：Supabase PostgreSQL。
- 身份认证：Supabase Auth 邮箱 OTP。
- 数据访问：Supabase SDK 与数据库 Row Level Security。
- 邮件：Resend，作为 Supabase Auth 自定义 SMTP 和业务提醒发送服务。
- 定时任务：Vercel Cron。
- 输入校验：Zod。
- 单元与集成测试：Vitest。
- 端到端测试：Playwright。

### 7.2 代码边界

采用单仓库模块化单体结构：

- `app/`：路由、页面、布局和 Route Handlers。
- `features/auth/`：登录表单、会话与授权逻辑。
- `features/letters/`：写信、封存、列表、启封、修改与删除。
- `features/reminders/`：到期查询、发送状态、重试和邮件模板。
- `components/`：可复用的信纸、信封、按钮、表单和反馈组件。
- `lib/db/`：数据库客户端、查询和生成类型。
- `lib/security/`：加解密、授权断言、速率限制与幂等工具。
- `lib/time/`：UTC、中国标准时间、快捷日期和倒计时计算。

业务规则放在可独立测试的服务函数中，不散落在页面组件内。API 层负责验证、授权和映射 HTTP 响应，不直接承载全部业务细节。

## 8. 数据模型

### 8.1 profiles

- `id`：与 Supabase Auth 用户 ID 对应。
- `email`：用于界面显示和提醒定位；公开接口不存在。
- `timezone`：MVP 默认 `Asia/Shanghai`。
- `email_reminders_enabled`。
- `phone_number`：预留，可为空。
- `phone_verified_at`：预留，可为空。
- `created_at`、`updated_at`。

### 8.2 letters

- `id`。
- `user_id`。
- `title`：封存前后均需在列表展示，因此不作为正文密文的一部分，但仍受 RLS 保护。
- `body_ciphertext`、`body_iv`、`body_auth_tag`、`encryption_version`。
- `created_at`。
- `unlock_at`：UTC 时间。
- `original_unlock_at`：首次设置值。
- `unlock_changed_at`：为空表示尚未修改。
- `opened_at`：用户首次成功阅读时间。
- `deleted_at`。
- `created_idempotency_key`：防止重复封存。

### 8.3 reminder_deliveries

- `id`。
- `letter_id`。
- `user_id`。
- `channel`：MVP 为 `email`，未来可为 `sms`。
- `event_key`：唯一标识某封信的本次到期提醒。
- `status`：`pending`、`sending`、`sent`、`failed`。
- `attempt_count`。
- `provider_message_id`。
- `last_error_code`、`last_error_message`。
- `next_attempt_at`、`sent_at`、`created_at`、`updated_at`。

数据库为 `(letter_id, channel, event_key)` 设置唯一约束。RLS 默认拒绝访问，再按用户所有权开放必要的查询；使用服务端高权限密钥的定时任务只能运行在受保护的服务端环境。

## 9. 加密与隐私边界

- 信件正文在 Next.js 服务端使用带认证的对称加密算法加密后写入数据库。
- 加密主密钥只保存在 Vercel 加密环境变量，不进入客户端包、日志或 Git。
- 每封信使用独立随机 IV，并保存加密版本以支持未来密钥轮换方案。
- 解密函数必须先完成会话、所有权、删除状态和到期时间检查。
- 日志不得记录验证码、会话令牌、正文、密钥或完整邮件内容。
- 标题为满足到期前列表展示而不加密，但仍是私密数据，只允许所有者读取。

这不是严格端到端加密。服务端在满足启封条件后有能力解密正文。MVP 选择这一边界，是为了兼顾账号恢复、服务端到期校验和未来通知扩展。

密钥丢失将导致正文不可恢复，因此正式开放前必须建立密钥离线备份和轮换文档；免费自测阶段同样不得随意更换密钥。

## 10. API 与授权

建议接口职责如下，最终路径可在实施计划中细化：

- `POST /api/letters`：创建并封存信件。
- `GET /api/letters`：返回本人信件元数据列表。
- `GET /api/letters/:id`：到期前仅返回元数据，到期后返回解密正文。
- `PATCH /api/letters/:id/unlock-date`：原子地修改一次启封日期。
- `DELETE /api/letters/:id`：软删除本人信件。
- `GET /api/export`：导出本人数据。
- `GET /api/cron/reminders`：受 `CRON_SECRET` 保护的提醒任务。
- `POST /api/reminders/:id/retry`：本人触发符合条件的提醒重试。

所有写操作执行以下共通步骤：

1. 验证登录会话。
2. 解析并校验请求体。
3. 重新查询资源所有权和当前状态。
4. 在服务端执行业务规则。
5. 使用事务、唯一约束或条件更新保证并发安全。
6. 返回稳定错误码和适合用户阅读的中文提示。

## 11. 提醒与时间处理

- 数据库统一保存 UTC 时间，界面使用 `Asia/Shanghai` 展示。
- Vercel Cron 每天运行一次，查询已到期且没有成功提醒的信件。
- Vercel Hobby 定时任务可能在设定小时内任意时间调用，因此产品文案为“到期日上午提醒”，不承诺精确分钟。
- Cron 接口使用 `CRON_SECRET` 验证来源，不能匿名公开执行。
- 任务需要锁定或条件更新待发送记录，防止并发任务重复发送。
- 发送成功后保存服务商消息 ID；失败使用有上限的退避重试，并允许后续人工触发。
- 即使提醒完全失败，用户访问网站时也能按服务端时间正常启封。

快捷日期与倒计时应由共享的时间模块计算，并对跨年、闰年、月底和时区边界编写测试。

## 12. 错误处理与恢复

- 网络错误：保留封存前本地草稿，提供重试，不自动创建重复信件。
- 登录邮件延迟：显示重发倒计时和排查提示，限制重复请求。
- 数据库写入失败：明确告知未封存成功。
- 重复提交：客户端禁用按钮，服务端使用幂等键和唯一约束兜底。
- 未到期访问：返回稳定的禁止状态，不泄露密文或正文长度等不必要信息。
- 第二次修改日期：返回业务冲突错误，页面同步显示已用完机会。
- 邮件失败：记录可诊断错误，下一周期重试，不影响启封。
- 免费配额或服务暂停：运行状态页或站长日志应能识别，不把故障显示为正常等待。

## 13. 测试与验收

### 13.1 单元测试

- 一年、五年、十年和自定义日期计算。
- 闰日、月底、UTC 与中国标准时间转换。
- 标题和正文长度校验。
- 加密后密文不等于明文，正确密钥可解密，篡改密文会失败。
- 到期判断和删除状态判断。
- 日期仅可修改一次。
- 提醒重试和幂等状态机。

### 13.2 数据库与集成测试

- 用户只能查询自己的信件。
- 未到期详情不返回正文。
- 并发日期修改只有一个请求成功。
- 重复幂等键只创建一封信。
- 重复 Cron 调用只产生一次成功发送。
- 删除后普通查询和启封均不可访问。

### 13.3 端到端测试

- 邮箱登录、写信、封存、列表和退出。
- 通过测试时钟或测试数据完成到期与启封流程。
- 本地草稿恢复。
- 删除和二次确认。
- 日期修改一次后禁用。
- 375px、390px、430px 视口及手机软键盘场景。
- 减少动态效果设置下无强制拆信动画。
- 弱网、刷新和重复点击不生成重复数据。

### 13.4 生产演练

- Vercel 生产链接可访问。
- Supabase 生产 RLS 已启用。
- 环境变量未暴露到客户端或仓库。
- 使用站长本人邮箱完成一次真实 OTP 邮件和一次到期提醒。
- 验证提醒失败日志与手动重试路径。
- 按部署文档从空环境复现关键配置。

## 14. 部署、成本与阶段策略

### 14.1 零成本自测

- Vercel Hobby 部署到 `*.vercel.app`。
- Supabase Free 保存数据和处理认证。
- Resend 测试域名只向 Resend 账号本人邮箱发送。
- 该阶段用于站长端到端测试，不对外承诺长期保存。

### 14.2 小范围外部测试

- 购买自有域名并绑定 Vercel。
- 在 Resend 验证域名，配置 SPF、DKIM，并作为 Supabase 自定义 SMTP。
- 继续使用 Resend、Vercel 和 Supabase 免费额度，直到达到容量或可靠性门槛。

### 14.3 正式运营前必须补齐

- 升级不会因低活跃暂停且提供备份能力的数据库方案。
- 自动备份、恢复演练和密钥离线备份。
- 监控、错误告警、邮件退信和投递状态处理。
- 隐私政策、用户协议、数据删除说明和服务期限承诺。
- 域名续费、账号所有权和服务交接流程。
- 获得合适资质后接入国内短信签名、模板和手机号验证。

不能以免费套餐为基础向用户作出“十年后必然可用”的无条件承诺。产品文案必须区分当前体验版与未来正式服务保障。

## 15. 后续扩展

按优先级考虑：

1. 自有域名和外部测试用户。
2. 数据备份、监控和付费稳定性升级。
3. 手机号绑定、短信验证码和短信到期提醒。
4. 图片或语音信件。
5. 匿名社区；需要重新设计公开授权、举报、审核、评论治理和管理员能力。

第二阶段功能不得提前污染 MVP 导航、数据权限或交互闭环。
